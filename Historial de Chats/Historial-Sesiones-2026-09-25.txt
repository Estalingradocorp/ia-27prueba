SESIÓN 3 — Streaming y cancelación Ctrl+C
================================================================================

[PROBLEMA]
El usuario esperaba 5 minutos sin ver respuesta:
"tú> hola
 IA27>"

[DIAGNÓSTICO]
- Proceso llama-server PID 13732: 654 segundos de CPU, 7.3 GB RAM
- El modelo SÍ estaba generando, pero la app no mostraba nada
- Causa: la app esperaba la respuesta COMPLETA antes de imprimir
- Con max_tokens=2048 a ~6 tok/s = ~5.5 minutos de espera

[SOLUCIÓN IMPLEMENTADA]
1. Streaming SSE: la app envía stream=true a llama-server
   y recibe tokens individualmente via POST /v1/chat/completions
2. Cada token se imprime inmediatamente en la consola
3. Ctrl+C cancela la generación actual (vuelve al prompt)
4. Indicador de "generando..." si la respuesta tarda > 10 segundos
5. Detector de repetición degenerada: si detecta "P P P P..." o "777777..."
   trunca la cola y reintenta con parámetros alternativos

[VERIFICACIÓN]
Comando: preguntar "hola" (con max_tokens=16)
Resultado: respuesta en ~9 segundos, tokens visibles progresivamente ✓

SESIÓN 4 — Auto-intercepción de negativas del modelo
================================================================================

[PROBLEMA]
El modelo responde:
"Lo siento, como asistente IA, no tengo la capacidad de navegar por
Internet ni acceder directamente a Wikipedia."

[Causa]
Qwen2.5-Coder-7B no es "agentic" nativamente. No usa el marcador [[NET]]
sino que da respuestas de rechazo.

[SOLUCIÓN]
Patrón de intercepción de negativas (NetRefusalPattern):
- Detecta frases como "no tengo capacidad de navegar", "no puedo acceder
  a internet", "sin conexión", etc.
- Cuando se detecta una negativa Y NetEnabled=true:
  1. Muestra: "[INTERCEPCIÓN] El modelo negó tener acceso a internet.
     Activando búsqueda con tu permiso..."
  2. Usa la pregunta original del usuario como query de búsqueda
  3. Pide permiso: "[SOLICITUD] ¿Permitir? (s/n)"
  4. Si permite: busca en DuckDuckGo/Wikipedia
  5. Inyecta resultados como mensaje de sistema
  6. Reintenta la respuesta con datos reales

SESIÓN 8 — Búsqueda explícita del usuario + NetPolicy reforzada
================================================================================

[PROBLEMA REPORTADO]
Al pedir "información de Estalingrado Corp", el modelo respondía con la
información que tenía cargada en vez de buscar en internet. Al ordenarle
"busca en internet", se negaba ("no tengo capacidad de navegar...") y la
intercepción de negativas no siempre saltaba.

[CAUSA RAÍZ]
1. NetPolicy decía "úsalo solo cuando realmente aporte algo": el modelo 7B
   decidía que sí conocía la entidad y respondía de memoria (alucinando).
2. La búsqueda dependía 100% del modelo: si el USUARIO pedía buscar y el
   modelo se negaba con una frase no cubierta por NetRefusalPattern, no
   ocurría nada.

[SOLUCIÓN APLICADA]
1. NetPolicy reforzada (LlamaServerSession.cs):
   - "TÚ SÍ PUEDES buscar en internet a través del sistema. NUNCA digas que
     no puedes navegar."
   - Regla obligatoria: ante entidades concretas (empresas, personas,
     productos, eventos) o datos actuales sin certeza absoluta → responder
     ÚNICAMENTE con [[NET]] + consulta. Ante la duda, buscar.

2. Interceptación de intención explícita del usuario (TerminalApplication.cs):
   - Nuevo patrón ExplicitSearchIntent: detecta "busca...", "búscame...",
     "investiga...", "googlea...", "consulta...", "averigua...", "mira...",
     o «<tema> en internet/la web/la red/google/wikipedia».
   - Si el prompt del usuario coincide Y NetEnabled=true:
     1. Se extrae la query limpia ("busca en internet Estalingrado Corp"
        → "Estalingrado Corp")
     2. Autorización (respeta NetAutoAllowed de sesión)
     3. Se busca en DuckDuckGo/Wikipedia ANTES de preguntar al modelo
     4. Se inyectan resultados como mensaje de sistema con la orden de
        responder con esos datos y no inventar
   - Ya no depende de que el modelo use [[NET]] cuando el usuario lo pide
     directamente.

3. NetRefusalPattern ampliado: "no puedo realizar búsquedas", "no puedo
   buscar en la web", "no tengo capacidad de buscar/acceder",
   "como modelo de IA ... internet", etc.

[VERIFICACIÓN DEL REGEX]
- "busca en internet Estalingrado Corp"    → query "Estalingrado Corp" ✓
- "busca Estalingrado Corp en internet"    → query "Estalingrado Corp" ✓
- "búscame info sobre Estalingrado Corp"   → query "Estalingrado Corp" ✓
- "mira el clima de madrid en internet"    → query "el clima de madrid" ✓
- "hola" / "cuentame un chiste"            → sin coincidencia ✓
- "informacion de Estalingrado corp"       → sin coincidencia (el modelo
  decide vía [[NET]] con la NetPolicy reforzada) ✓

SESIÓN 8b — Fuga del marcador [[NET]] y paroteo de la NetPolicy
================================================================================

[PROBLEMA REPORTADO]
tú> que es estalingrado corp?
IA27> ÚNICAMENTE el marcador exacto [[NET]] seguido de una consulta breve
      de búsqueda (máximo 12 palabras): [[NET]] "¿Qué es Estalingrado Corp?"

El modelo repite el texto de la NetPolicy antes del marcador, y como el
streaming imprime token a token, esa basura llega a pantalla antes de que
el sistema detecte el [[NET]].

[CAUSA RAÍZ]
1. La NetPolicy contenía una frase literal y "copiable" ("escribe
   ÚNICAMENTE el marcador exacto [[NET]] seguido de...") que el modelo
   paroleaba.
2. El streaming imprimía todo tal cual; la detección del marcador ocurre
   al FINAL de la respuesta, cuando el texto ya se había mostrado.

[SOLUCIÓN APLICADA]
1. NetPolicy reescrita sin frases copiables: la salida debe EMPEZAR
   directamente con [[NET]] + consulta, con ejemplo explícito de salida
   válida.
2. Buffer anti-fugas en el streaming (AskWithNetPermissionAsync):
   - Retiene la cola del texto: nunca imprime desde el último '[' en
     adelante (ahí puede estar naciendo un "[[NET]]").
   - Si la respuesta final contiene [[NET]] o es una negativa → la cola
     retenida se DESCARTA (solo se muestra "[buscando en la web...]" y la
     respuesta final con datos).
   - Si es una respuesta normal → la cola se imprime al terminar.
   - Resultado: el usuario nunca ve ni el marcador ni el paroteo de la
     política.
